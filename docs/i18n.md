# i18n 接入规范（多国语言系统）

基础设施已就绪：`i18next` + `react-i18next` + `i18next-browser-languagedetector`，
资源静态打包、初始化同步完成（无 Suspense / 无翻译闪烁）。当前语言：
`zh-CN`（源语言、兜底语言）与 `en`。基线：git 标签 `pre-i18n-baseline`。

## 目录结构

```
src/i18n/
  index.ts                 # i18next 初始化（detector + react 绑定）
  resources.ts             # 资源汇总 + AppLocale 类型 + SUPPORTED_LOCALES
  resources.d.ts           # t() 键的类型声明（以 zh-CN 资源为准）
  locales/
    zh-CN/common.json      # 源语言
    en/common.json         # 目标语言
```

入口接线在 `src/main.tsx`：`import '@/i18n'`（放在样式导入之前，保证渲染前初始化完毕）。

## 组件接入方式

```tsx
import { useTranslation } from 'react-i18next'

function Nav() {
  const { t } = useTranslation()
  return <span>{t('nav.projects')}</span>          // 模块级常量只存键：labelKey: 'nav.projects'
}
```

- 键名规范：`<域>.<用途>`，小驼峰。域与 feature 目录对应：`nav.*`、`projects.*`、
  `review.*`、`canvas.*`、`settings.*`、`me.*`、`chat.*`；跨页面共用文案放 `common.*`。
  所有命名空间先都放 `common.json`，等某域体量大了再拆 `locales/*/review.json`
  （拆分时在 `resources.ts` 挂新 namespace、`resources.d.ts` 加类型）。
- 插值：`t('projects.count', { count: 3 })` → `"共 {{count}} 个项目"`。
- 复数：zh-CN 用 `_one`/`_other`（`count_one` / `count_other`），en 必须区分。
- 日期/相对时间：不要自己拼，用 `Intl.DateTimeFormat(locale)` / `Intl.RelativeTimeFormat(locale)`，
  locale 从 `i18n.language` 取。

## 迁移范围（什么要迁、什么不迁）

**要迁**：用户可见的一切 UI 文案——按钮、标题、占位符、toast（sonner）、
`aria-label`、错误提示、对话框文案、空状态。
**不迁**：代码注释、git 提交信息、日志（`console.*`）、专有名词（OpenTreeLearn）、
发给 LLM 的 prompt（除非做 prompt 本地化，另行立项）。

## 迁移一个组件的步骤

1. `const { t } = useTranslation()`
2. 字面量换成 `t('域.键')`；模块级常量存键名（见 `AppShell.tsx` 的 `NAV_ITEMS`）
3. `zh-CN/common.json` 加键（源语言为准），`en/common.json` 同步补翻译
4. `pnpm typecheck` —— 键写错或 en 缺键会在此报错（`resources.d.ts` 保证）

已完成示例：`src/components/AppShell.tsx`（导航标签、载入文案、aria-label）。

## 新增一门语言

1. `src/i18n/locales/<code>/common.json`（从 zh-CN 复制后翻译，键结构必须一致）
2. `resources.ts` 挂条目；`index.ts` 的 `supportedLngs` 加 `<code>`
3. 无需动组件
