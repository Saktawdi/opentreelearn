# i18n 接入规范（多国语言系统）

基础设施已就绪：`i18next` + `react-i18next` + `i18next-browser-languagedetector`，
资源静态打包、初始化同步完成（无 Suspense / 无翻译闪烁）。当前语言：
`zh-CN`（源语言、兜底语言）与 `en`。基线：git 标签 `pre-i18n-baseline`。

## 目录结构

```
src/i18n/
  index.ts                 # i18next 初始化（detector + react 绑定 + <html lang> 同步）
  resources.ts             # 资源汇总 + AppLocale 类型 + SUPPORTED_LOCALES
  resources.d.ts           # t() 键的类型声明（以 zh-CN 资源为准）
  locales/
    zh-CN/*.json           # 源语言：每 feature 一个命名空间文件
    en/*.json              # 目标语言
```

命名空间与 feature 目录一一对应：`common`（导航/跨页面共享，含 AppShell）、
`components`（BootstrapError/RouteError/ui 原语）、`projects`、`review`、`canvas`、
`settings`、`me`、`chat`。stores/services 等共享层的用户可见文案（toast、错误提示）
统一放 `common`。

入口接线在 `src/main.tsx`：`import '@/i18n'`（放在样式导入之前，保证渲染前初始化完毕）。

## 组件接入方式

```tsx
import { useTranslation } from 'react-i18next'

function Nav() {
  const { t } = useTranslation()                 // 跨页面共享文案：默认 common 命名空间
  return <span>{t('nav.projects')}</span>
}

function ProjectsPage() {
  const { t } = useTranslation('projects')       // feature 内文案：传自己的命名空间
  return <h1>{t('page.title')}</h1>              // 键名不带命名空间前缀
}
```

非 React 上下文（store/service 的事件回调、工具函数）：`import i18n from '@/i18n'`，
调用点用 `i18n.t('common:xxx')`。模块级字符串常量不能在模块加载时取译文——改成存键、用时解析。

跨命名空间共享词表（多处消费方分属不同 feature）：键放 `common`，消费方显式写
`` t(`common:grade.${grade}`) ``。已有：`grade`/`gradeHint`/`band`（评分档措辞）、
`hint`（节点操作提示）、`noteLabel`/`noteHint`（内置标注标签）。

**双轨字段（数据 vs 展示）**：`domain/notes.ts` 的内置标签同时喂 AI 上下文与导出数据。
`name`/`hint` 恒为中文不变，另加 `labelKey`/`hintKey` 供 UI 按当前语言解析 ——
模型口径、落库数据、.tree 导出全都不受语言切换影响。新增内置标签照此办理。

**不迁的边界（重要）**：`src/domain/context/`、`src/services/llm/`（tools/registry、
derive、review、model-catalog、llm/tools/*）里绝大部分中文是**发给 LLM 的系统提示词
与上下文组装**——保持中文原样。这里的取舍：切换界面语言不改变模型行为，prompt 的
质量由中文版本保证（后续若要模型输出语言跟随界面语言，是独立议题，需单独评估）。
其余不迁项：代码注释、console/logger、测试文件、服务端透传的 envelope.msg。

- 键名规范：`<对象/区域>.<含义>`，小驼峰，按组件结构自然分组；插值 `{{count}}`。
  键写在所属 feature 的命名空间文件里（如 `src/i18n/locales/zh-CN/review.json`），
  两份语言键集合保持一致；en 缺键、t() 写错键由 `pnpm typecheck` 拦截。
- 复数：仅当文案带数量词才用复数键——en 写 `_one`/`_other` 两份，zh-CN 只写
  `_other`（中文复数不分型），`t` 调用传 `{ count }`。
- 日期/相对时间：不要自己拼，用 `Intl.DateTimeFormat(locale)` / `Intl.RelativeTimeFormat(locale)`，
  locale 从 `i18n.language` 取。

## 迁移范围（什么要迁、什么不迁）

**要迁**：用户可见的一切 UI 文案——按钮、标题、占位符、toast（sonner）、
`aria-label`、错误提示、对话框文案、空状态。
**不迁**：代码注释、git 提交信息、日志（`console.*`）、专有名词（OpenTreeLearn）、
发给 LLM 的 prompt（除非做 prompt 本地化，另行立项）。

## 迁移一个组件的步骤

1. `const { t } = useTranslation('命名空间')`（跨页面共享文案用默认 common）
2. 字面量换成 `t('键')`；模块级常量存键名（见 `AppShell.tsx` 的 `NAV_ITEMS`）
3. `src/i18n/locales/zh-CN/<命名空间>.json` 加键（源语言为准），`en/<命名空间>.json` 同步补翻译
4. `pnpm typecheck` —— 键写错或 en 缺键会在此报错（`resources.d.ts` 保证）

已完成示例：`src/components/AppShell.tsx`（导航标签、载入文案、aria-label）。

## 新增一门语言

1. `src/i18n/locales/<code>/` 复制 zh-CN 全部 8 个命名空间文件并翻译（键结构必须一致）
2. `resources.ts` 挂条目；`index.ts` 的 `supportedLngs` 加 `<code>`
3. 无需动组件

## 语言切换与运行时行为

- 切换：`i18n.changeLanguage(code)`；detector 已配置自动把选择持久化到
  `localStorage['ootl.lang']`。切换器在「配置」页。
- `<html lang>` 由 `i18n/index.ts` 的 `languageChanged` 监听自动同步。
- 测试环境（vitest node 环境）取不到浏览器语言，detector 落到 fallback `zh-CN`，
  断言渲染文案的测试始终看到中文，无需特殊处理。
